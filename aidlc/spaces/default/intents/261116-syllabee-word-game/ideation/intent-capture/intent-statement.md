# Intent Statement: Syllabee

## Problem Statement

- Syllabee is a five-letter word-guessing web game: a player enters a shared passcode, plays one game on one page (six attempts, five letters, no size or difficulty options) and logs out. [Q1]
- The product is called Syllabee, never "Wordle", and uses its own word list. [Q1]
- The work is a practice run for building software with the AI-DLC process. [Q2]

## Target Customer

- A small private audience (family, friends, team) who are given one shared passcode; there are no accounts, no sign-up and no personal data collected. [Q1]
- Besides the players, the only stakeholder is the product owner. [Q5]

## Success Metrics

- Each release (v0.1, v0.2, v0.3) is live on staging, smoke-tested, with all checks green. [Q3]
- Production is live at v1.0 and the invited group actually plays it. [Q3]

## Initiative Trigger

- The trigger is a practice run for building software with the AI-DLC process. [Q2]

## Initial Scope Signal

- Workflow-selected scope: `mvp`. [scope]
- Release order (user-confirmed): v0.1 enter passcode, see an empty board, log out; v0.2 play one full game with correct colouring; v0.3 resume a game after refresh and see win/loss stats. [Q1]
- Left out of this first version (user-confirmed): multiple word lengths, hard mode, theme picker, leaderboards, social sharing, user accounts or per-user passcodes, AI hints, multiple machines or replicas, any paid third-party service. [Q1]
- Nothing further is excluded beyond that list. [Q7]
